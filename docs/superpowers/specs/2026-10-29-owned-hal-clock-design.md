# Controlled macOS HAL renderer and callback clock — experimental design

Status: controller-selected reversible experiment under the existing addon-only implementation/testing request, after independent builder review. This is a technical implementation choice, not user approval of production audio routing. Native implementation and captured proof are still outstanding. The c33f6d0 AE renderer remains the default. No Kodi core, recorder, power-policy, device-setting, priority or unrelated-job changes. Normal Kodi Pause/Resume, exact source order, no unintended gaps/replay, full prefix/tail and natural EOF remain required. First native audio/control trials keep actual beacons disabled until the distinct callback-clock provider is implemented, reviewed and captured qualification passes. Kodi app/recorder manifests remain unchanged; the addon lab capability manifest may explicitly advertise the experimental backend.

The fixture mode replaces only owned PCM output with one public CoreAudio IOProc, preserving AAC transport/decode/PTS0/hash proof, source order, session binding and the video-only VideoPlayer control host. No automatic AE/HAL fallback or production activation. The loopback route, nonce/incarnation, timeline hash, actual caller and every existing ownership/control fence remain mandatory.

Virtual/physical formats agree. Device latency is 70 frames, stream latency 690, safety offset 74; all statuses succeeded and default-ID readback matched. Artifacts, helper source and commands are in `owned-clock-beacons-validation/hal-readonly-preflight/`. AE retains integrated volume/routing but has the observed starvation and indirect clock evidence. Its public addon SDK exposes no safe worker pthread identity/lifetime for QoS overrides; thread-name scanning is excluded. AUHAL adds conversion/routing machinery without resolving mute notification timing. Direct IOProc gives the clearest application delivery boundary, with substantial lifecycle, buffering and control responsibilities; OS/device failures remain possible.

## Code lifetime and bounded teardown

Before any callback/listener registration, use public `dladdr` on an own-code address to obtain the module path/base, then acquire one process-lifetime reference with `dlopen(path, RTLD_NOW | RTLD_LOCAL | RTLD_NOLOAD)`. Verify identity through an own exported symbol and `dladdr` base/path; never use private Kodi handles. Public macOS `dlopen(3)` says NOLOAD returns a ref-counted handle only for an existing image; repeated opens increment references. `dladdr(3)` and SDK `dlfcn.h` expose the path/base and flags. Capture these checks; unsupported/mismatched pinning fails before registration. At most one pin per loaded module/process. Never release the final self-pin from code it could unload. This explicit memory-until-Kodi-exit cost is controller-approved for the experiment, not production approval.

Callback/listener context and its non-real-time cleanup ownership must be independent of Addon instance lifetime and SDK pointers. Teardown first atomically silences/revokes, then stops/destroys the owned IOProc and removes listeners off the callback thread. Public pending-entry closure after listener/IOProc removal is not established by the inspected contract. Once a context is passed to any callback/listener registration API, retain that revoked independent context and module code until process exit, even after successful OS cleanup; quarantine the session slot and deny all new HAL sessions in that process. This bounds retention to one exposed context per process and makes delayed/pre-entry callbacks safe without assuming an undocumented barrier. A clean result means OS cleanup completed with retained context, not that context was reclaimed or pending entry proved impossible. Never-exposed contexts may be released safely. Atomically arbitrate terminal success versus timeout before any claim release; stale timeout readers cannot affect a later owner. If cleanup fails or exceeds 2 seconds, keep the same retained context/code quarantined and let Kodi cancellation/destruction return. A timed-out API cannot safely be killed: any still-running cleanup owner must retain only module-owned independent state, not touch destroyed instances. Bound this to one quarantined session, not repeated abandoned workers. Prove lifetime and timeout paths with a separate fake-DLL/harness before real registration; inability to establish public pinning/quiescence fails closed.

## Output and realtime ownership

Register a C `AudioDeviceIOProc`, start only its returned ID, and never alter device rate, buffer size, gain, hog mode or routing. No aggregate device, conversion, manual thread priority or extra audio worker. Listener/readback guards pin default identity, alive state, nominal rate, stream configuration and virtual format. Register listeners before coherent double readback; retain full non-real-time checks/cadence. Change permanently retires this session and requests stop rather than following the route.

Use a preallocated single-producer/single-consumer PCM ring capped at 192000 frames, with bounded decoder backpressure. The callback alone commits source consumption. Existing mutex-protected FIFO access must be replaced for this path with a tested lock-free handoff; it cannot execute inside the IOProc. Verify lock-free indices, checked capacity, no overwrite and pre-touched storage. A preallocated 4096-record evidence ring publishes complete callback records; overflow retires instead of overwriting unseen evidence. The existing non-real-time owner drains it.

Callback work is bounded copies, gain multiplication, zeros and atomic metadata publication: no allocation, logging, formatting, I/O, property queries, Objective-C work, mutexes or waits. Require the exact 512 requested frames and pinned layout every callback. Invalid size/layout retires with zero output/no source advance. The public `AudioDeviceIOProc` contract guarantees output memory is zeroed on entry: the wrapper validates the exact layout before any writes, then returns 0 without traversing or clearing arbitrary malformed buffers. It does not change fixed-format `mDataByteSize`. Valid pinned storage may be explicitly cleared with bounded work. Fake wrapper tests supply the documented zero-on-entry state and verify unchanged malformed storage plus sentinel guards; the pure core only receives validated caller-owned storage. Missing PCM produces an explicit shortfall and retirement, never a blocking wait or hidden gap. Live-HLS starvation, PTS discontinuity and lost ownership are failures, not problems this fixture promises to eliminate.

## Startup, pause and callback boundary

Keep the proven rawvideo host, marker, actual VideoPlayer caller, 60-frame lead budget and 30-second native-open deadline. Prepare/prefill without consuming source. Nonzero output requires real onAVStarted acknowledgement, retained sample-zero proof, coherent device guards and valid acknowledged gain state. First consumed frame is source sample 0; no synthetic callback/resume.

The callback uses its own complete current control snapshot plus a capacity-one SPSC pending offer. A stalled or busy publisher never invalidates that current snapshot or inserts silence while its lease remains valid. Release publication queues an offer; it is not an applied acknowledgement. The final independent native-gate load is block acquisition and its linearization point. Native pause/route/stop before this point prevents consumption; a fence after it may allow one acquired 512-frame block to finish. Require the selected lease to cover scheduled block END. Never compare ordinary publication sequence to cancel acquisition. Applied epochs, resume grant, intent and exact lease timestamps reach the owner only through acquired evidence records. Pending genuine changes revoke tracking, not valid current audio; unchanged renewals do neither. The complete binding contract and deterministic tests are in [HAL control publication](2026-10-29-owned-hal-control-publication.md). No callback-owned plain memory may be read by the owner. Already submitted hardware output cannot be recalled.

Native DemuxSetSpeed fences consumption independently of the serialized publication owner. Keep the native speed/retirement gate separate from offer sequence and tracking intent. Only a new authenticated playback transition may grant the exact native resume epoch; gain renewals carry the previous grant unchanged and cannot resume. Callback evidence, not successful enqueue, acknowledges effective resume. Test stalled publication, busy backpressure, and pre/post-acquisition pause/resume/route/stop schedules as specified in the publication contract.

Normal Kodi callbacks/native speed fences retain existing stale-command rules. Pause freezes source consumption and emits zeros. Resume continues the next unconsumed frame. Acknowledgements identify the first effective output-host time/source boundary, not merely when the owner read a command. Pending changes invalidate tracking until effective; no query crosses an unapplied boundary. Cancellation revokes first and wakes the independent non-real-time owner.

## Gain and normal Kodi controls

`xbmc.Monitor.onNotification` supports sender `xbmc`, method `Application.OnVolumeChanged`, and volume/muted JSON. Exact core `ApplicationVolumeHandling.cpp:58–73,111–155`, `XBPython.cpp:171–177,472–482` provide this route. `AnnouncementManager.cpp:322–342,398–423` and `legacy/CallbackHandler.cpp:38–43,64–92` queue delivery twice, without a source timestamp, revision or deadline. Peripheral mute can return before announcement. Limit this experiment to the read-back built-in default device without a peripheral/hardware-mute route; production parity remains separate.

Register Monitor before the initial property read and start at zero gain. One Python control owner serializes `Application.GetProperties` queries/publications at 100 ms nominal cadence and on notification hints. Notifications never directly overwrite gain. Read back volume and actual muted state, strictly validate types/ranges, and retain local Mach request-start/end brackets. Query width must be at most 50 ms; invalid/late queries retire. Initial nonzero output requires request-START age at most 100 ms plus native acknowledgement. Gain lease expires 500 ms after request START, superseding the earlier completion-based proposal. This does not guarantee detecting a mute occurring during an unversioned read; captured response tests cover observed latency.

Use a separate exclusive sequential gain-command namespace in the pinned session directory, bound to nonce/incarnation/backend/device generation. Include transport revision, request bracket, issue/expiry, observed volume/muted and effective gain. Native rejects malformed, missing-next, stale, foreign or replayed commands, and acknowledges the applied revision/boundary. Every refresh increments transport revision; effective gain epoch changes only when actual gain/mute changes. Unchanged renewals do not reset acquisition. No gain command can revive a retired or paused playback generation. Publish playback, ownership and gain coherently as one effective snapshot.

Mirror Kodi's exact curve (`ActiveAE.cpp:408–409`, `AEUtil.h:116–153`): dB = 60 × (integer_percent/100 − 1); multiplier is zero at/below −60 dB, otherwise 10^(dB/20), with values at least 0.99 clamped to 1. Compute off the callback thread, not linear percentage gain. Muted means multiplier zero. Controller accepts rounded integer fidelity: at most ±0.5 percentage point (approximately 0.3 dB away from zero/top clamp); rounded zero may silence an underlying value below 0.5%. This limitation is explicit, not full fractional-volume parity.

Ordinary muted playback consumes source at zero gain; pause freezes it. Muted/zero-gain segments never qualify. Lease expiry/malformed state permanently retires, stops consumption and silences; no automatic recovery or fixed-gain fallback. Preregister captured response at most 250 ms from an action request to output change for a state held at least 250 ms; tests use 500 ms dwell, integer volumes 100/90/75/0 and mute/unmute. Rapid opposing commands may coalesce before an authoritative read: the final stable value must meet 250 ms from its request, with no stale old value after a newer acknowledgement. Test both superseded and observed intermediates. Failure blocks this mode, not retuning. The 500 ms lease is a separate stale-controller safety deadline, not a responsiveness guarantee or zero-latency promise.

## Callback timing and query contract

[Apple's IOProc contract](https://developer.apple.com/documentation/coreaudio/audiodeviceioproc) describes scheduled hardware handoff, not acoustic receipt. Retain raw ticks and exact Mach timebase. Each committed segment records schema/backend, session/incarnation, sequence, device/stream generation, playback revision/epoch, gain transport revision/effective epoch, source range, requested/consumed/copied/zero counts, applied gain/mute, timestamp flags, output sample time/host ticks, `inNow`, callback entry/exit and in-flight generation. Preserve original raw-row hashes and lossless record order.

Output sample times must be finite exact integers within double's exact integer range, advancing by the PRIOR requested frames, including pause/zero blocks. Require host-tick advance versus prior requested frames/48000 to agree within one source frame; larger deviation or rewind permanently retires. Use checked rational ticks/timebase arithmetic. Require output-host time minus callback-entry Mach time to be nonnegative and at most 100 ms. These thresholds are predeclared, never fitted to recordings.

After draining callback records, the native owner publishes a query at 20 ms cadence, with query bracket at most 5 ms and q its checked integer midpoint. Python accepts only these native queries no older than 100 ms; it never substitutes Python read-now extrapolation. At native query q, find exactly one committed source-bearing segment covering the half-open interval [output_host_ns, output_host_ns + copied_frames × 1e9/48000). Map source frame = source_start + floor((q − output_host_ns) × 48000/1e9). Use unshifted `inOutputTime`: ZERO additional device-latency offset for this candidate. The independent captured bound remains 21.333 ms; failure does not authorize a fitted correction.

Initial startup readiness is distinct from a qualified source position. Before releasing source, collect nine native readiness observations at the existing 20 ms cadence spanning at least 120 ms over real zero-output callbacks with no source consumption. Require coherent session/device/playback/gain/native-speed generations, valid timestamp continuity, callback/query freshness and live gain leases; these observations have no mapped source position and cannot feed tracking or authorize beacons. Relevant state changes invalidate readiness; unchanged gain renewals do not. Opening this one-time source-delivery gate is not itself a resume or gain change and does not reset that readiness. At release still require real onAVStarted, sample-zero proof, every fence, request-start age at most 100 ms and lease coverage through block END, within the existing startup/host-lead limits. The first source-bearing query qualifies only from its own unique, actually copied unmuted segment at q; no readiness row supplies mapping or acoustic proof. After playback begins, ordinary resume and genuine gain changes retain the existing nine-query reacquisition rule. No threshold, cadence, source placement, fitted offset or backfill changes.

The provider reports HISTORICAL source position at native q, never current Python read time. Preserve q, its query bracket and original row hash through snapshot, tracker and beacon audit; waveform comparison is at q and the 21.333 ms bound applies there. Revalidate current callback/native-control/output/gain generations before tracker mutation and again before queue authorization, without extrapolation or backfill. Separately retain the existing threshold-to-decision bound: 100 ms freshness + 20 ms native observation tick + 21.333 ms clock bound = 141.333 ms. HTTP receipt latency is separate. This states the existing owned contract, not a relaxation.

Tiny timestamp gaps/overlaps inside the one-frame continuity allowance yield unqualified queries whenever coverage is not unique; no interpolation or extrapolation. Also require latest callback-entry age at most 40 ms, current gain lease, coherent ownership/control/output/applied-gain generations across the query bracket, and matching effective acknowledgement boundary. Old segments retain their actual epochs, never relabeled. Pending resume/gain change invalidates tracking; requalify only after its effective boundary and 9 consistent native queries spanning at least 120 ms. Missing evidence, invalid flags, shortfall, stale state or permanent retirement never qualify. The AE provider and frozen v2 estimator remain unchanged; this is a distinct schema/provider, not disguised AE GetDelay. Scheduled evidence cannot universally prove audibility.

## EOF and acceptance

Copy the exact final source frames, including a partial final block, then zeros. Maintain valid gain leases until the final scheduled source END. After that END, enter terminal zero-only state: no clock/beacons, no consumption, and lease expiry cannot convert natural EOF into failure. Keep context and host alive until exactly final scheduled source END + 1 second as the fixed empirical lifetime safeguard; add no device/stream/safety latency. Cancel/error bypasses the normal hold. Then perform bounded cleanup/quarantine above. Captured natural EOF must occur within 5 seconds of the final audible source end, with full prefix/tail preserved; a hold or timestamp alone proves neither.

Builder verification must cover fake-DLL retention/unload, cleanup hangs/failures, lock-free rings, race linearization, leases/renewals, opposing controls, sample/host timestamp boundaries, overflow and partial EOF. Real tests must validate actual buffer layout, route/gain failures, normal control response and independent clock bounds before beacon activation. Final audio acceptance still needs two complete unprofiled runs with normal pauses, no unrequested gaps/replay and unchanged recorder/core/jobs. These are controller choices for a reversible fixture experiment, not claims of an already approved or successful backend.

## Preselection cancellation clarification

A shared atomic mode/latch handoff may defer abort until backend selection and stable pointer publication. Unknown-mode abort touches only the latch; HAL abort uses the stable facade and source-stop atomics. Publish AE mode only after its authority/source pointers exist, then claim a latched early abort once. This intentionally changes only early AE startup cancellation to avoid lost cancellation or concurrent pointer access. Preserve the initialized AE abort block and renderer body byte-for-byte. Test canceled Open before selection, during registration, and both backend handoffs; no broader AE behavior change is authorized.
