Controlled raw AAC / fragmented MP4 capture: bounded positive result

The unchanged reviewed native build 38d3f58 and unchanged Kodi core b5d4848
played the complete 180.032-second source through four normal Kodi pauses and
natural EOF. All 8,439 native source packets were raw_aac, with 8,641,536 decoded
and accepted frames. Actual native timestamps use 1,000,000 ticks per second;
the MP4 container uses 48,000. Source payloads and decoded PCM match the TS
reference byte for byte.

The recording contains 11,046,400 frames and zero timestamp discontinuities.
Independent per-channel scans at 0.5 ms resolution found only the four requested
pauses. Dense 40 ms source comparisons and 1 ms seam comparisons detected no
additional gaps or repeated source blocks. This is not bit-exact single-sample
equivalence. The long pause retained source around 85.31 seconds while the live
playlist had advanced to around 98–100 seconds.

The frozen offline V2 estimator retained all 132 independently qualified points
as valid: errors ranged from -7.21738 to +1.61048 ms, with zero violations of the
predeclared 21.33333 ms limit. No fitted offset or qualified-point exclusions
were used. The raw clock also passed this run; its earlier failures still apply.

The tested profile had audiooutput.lowlatency=false. Pause response was about
645–710 ms and resume response about 108–156 ms. Startup, pause tails, acquisition,
drain, device changes and physical-speaker timing remain unqualified. This
fixture has a fixed two-byte AAC-LC configuration, zero initial padding and no
skip/discard side data; changing initialization segments, other priming/edit
lists and general streams are not covered. No production beacons are enabled.

helper's identity check failed while Kodi remained alive. It is preserved as
incomplete evidence. Shared-log sink warnings occurred outside the successful
retry's 08:52:14Z–08:56:04Z window and were retained separately.
